<objective>
The credential-store base of the OAuth coding-plan chain (AUTH-02): a read-only
reader over the desktop's `~/.zcode/v2/credentials.json` with the plaintext /
`enc:v1:` / `enc:v2:os:` dispatch ladder, the legacy v1 fallback loader ported
per the reference behind the existing KeyLoader seam (D-03 — user choice for
completeness), and per-entry isolation with the unknown-prefix never-plaintext
rule. Locked by synthetic-fixture vectors only — CI never touches a real store.

Purpose: every later step of the chain (PAT mint, accountScope, snapshot
entitlement) reads its login material through this reader; a wrong layout or a
plaintext downgrade here corrupts everything downstream silently.

Output: `internal/interact/credstore.go` + the v1 sibling loader in the
KeyLoader family, both test-locked, `-race` green.

**User story (phase goal, MVP framing):** As a user on a z.ai individual coding
plan, I want the wrapper to read my desktop login from the same encrypted store
the desktop uses — both the field-proven `enc:v2:os` layout and the legacy
`enc:v1` fallback — so that authentication works on whatever layout my machine
has, without the wrapper ever writing or leaking a credential.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| desktop credentials.json -> wrapper reader | The store's values are desktop-controlled bytes; a malformed or hostile-shaped entry must isolate, never crash the process nor leak plaintext |
| decrypt output -> reply-construction scope | Decrypted credential values cross into chain consumers; they must never reach logs, captures, or errors |

| T-06-03 | Tampering | fp24/key mismatch silently decrypting with the wrong key | medium | mitigate | The v2 arm verifies hex(sha256(key))[:24] against the blob's fp24 before GCM open; mismatch is a coded per-entry skip (existing key-mismatch code family) |
