<objective>
The coding-plan account snapshot (AUTH-02, Pattern 2): extend
`internal/hostsvc/snapshot.go` with BuildAccount — the NON-empty
provider/updateAccountConfig overlay mirrored from the desktop's bundled builtin
table (zhipu-account rules only), with per-provider states and the entitlement
gate seam. The Phase-5 empty-overlay builder stays byte-untouched.

without this overlay every account:* model reads unentitled and the registry
never surfaces the coding-plan models (the reference's own header doc: a push
turned 3 models into 21). This plan is the snapshot half of success criterion 1.

Output: BuildAccount + its vector locks; the existing empty-overlay builder and
its goldens untouched, `-race` green.

**User story (phase goal, MVP framing):** As a user on an individual coding
plan, I want the wrapper to tell the backend exactly which account providers my
desktop's own builtin table declares — entitled because my desktop login says
so — so that my GLM models actually appear in the registry instead of silently
reading unentitled.
</objective>
