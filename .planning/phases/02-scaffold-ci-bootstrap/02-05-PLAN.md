## Phase Goal

**As a** later-phase implementer on this repo, **I want to** have strict quality gates — strict pinned lint, CI, and a protected `master` modeled on Djarvur/goswitch — enforced from the very first code commit onward, **so that** all feature code lands under the same gates and later phases merge only through green PRs.

<objective>
Apply real branch protection to `master` (SCAFF-03, D-01) as the LAST task of the LAST plan of the
phase — after all Phase-2 work is on master with green observed checks (plan 02-04) — verify it by
reading the API state back, prove direct pushes are rejected (GH006), and only then flip the GSD
`branching_strategy` to `phase` so Phases 3+ work on `gsd/phase-*` branches via PRs.

Purpose: the phase goal's third clause — "master is protected: direct pushes are rejected, merges
require the configured checks, and the protection setup is documented in the repo" — is the
phase's closing gate; applying it earlier would block the phase's own pushes (RESEARCH Pitfall 5).
Output: `protection-body.json` (the documented, re-applicable PUT body), applied + verified
protection, the config flip, an honest record of anything the API refused.
</objective>
