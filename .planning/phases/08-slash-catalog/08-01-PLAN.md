# Plan 08-01 — The slash catalog: `available_commands_update` on session/new

## Objective

The Orca card's composer autocomplete lists ZCode skills and `/model` for the wrapper
card: on every `session/new` the front emits ONE `session/update` notification with
`update.sessionUpdate = "available_commands_update"` carrying `availableCommands`
(skills scanned from SKILL.md frontmatter + the `/model` entry), within the client's
9 s discovery-scan budget (CAT-01..04; CAT-05 is the field pass).

## Wire truth (docs/protocol/acp-client-dialect.md, "slash-command catalog surface")

- Discovery flow: `initialize` → `session/new` → wait ≤9 s for ONE `session/update`
  with `update.sessionUpdate === "available_commands_update"` → teardown
  (`session/delete` iff `sessionCapabilities.delete` advertised; otherwise the
  disposable `--session-dir` arm kills the process — the wrapper advertises NO delete
  capability, CAT-04).
- Item shape: `{name, description?, input?: {hint?}}`; the omp dialect renders every
  item as `kind: "command"` (no skillDescription hook) — skills and commands ride the
  same list; the `/model` prompt form is `/model <selector>` (`resolvesSelectorsFrom:
  "18.1.9"`; the wrapper's stamp is `18.1.9+zacp.0`).

## Tasks

### Task 1 — The skill catalog scanner (TDD)

`internal/acpfront/catalog.go`: `SkillCatalog` with injectable roots
(`CatalogRoots []string` Front option; main() resolves `~/.zcode/skills` +
`~/.zcode/cli/plugins/cache/**/skills` glob). Scan: every direct child dir's
`SKILL.md`; frontmatter `name:`/`description:` (the --- fenced head); entries sorted
by name; missing roots → empty; unreadable/frontmatter-less children skipped silently
(structural log). Deterministic; pure function of the roots.

- RED: `TestSkillCatalog` — fixture roots (testdata/catalog/{alpha, beta, broken}),
  assert names/descriptions/order, the broken entry skipped, the missing root empty.
- GREEN: the scanner.
- Lock: the glob resolution (`DefaultCatalogRoots(home)`) — unit test with a fake
  home tree.

### Task 2 — The emitter on session/new (TDD)

On session/new success (before the reply returns), the front sends ONE ACP
`session/update` notification to the client with
`update: {sessionUpdate: "available_commands_update", sessionId, availableCommands: [...]}`
— skills (alphabetical) then the `/model` item (`name: "model"`, description naming the
switch, `input: {hint: "<selector>"}`). No delete-capability advertisement (CAT-04).

- RED: tracer-harness test — `TestSessionNewEmitsCommandCatalog`: after session/new the
  client sees the available_commands_update frame with the fixture catalog + model item;
  the emit is exactly ONE notification; a second session/new emits again (per-session).
- GREEN: the emitter in the session/new path (find the front's client-notification
  writer — the same surface the pump's chunk notes ride), wired with the catalog roots.
- Lock: the no-roots arm (catalog = just `/model`, never an error, never a hang).

### Task 3 — Corpus row + binary E2E (TDD)

- Corpus row `catalog-emission`: replays the backend session/create and byte-locks the
  client-visible available_commands_update frame on the ACP tee (the fake stays
  backend-only; the catalog is front-side from the injected fixture roots).
- Binary E2E: the discovery argv `omp acp --session-dir <dir>` against the built
  binary with fixture roots — the frame appears on the wire within the budget, and the
  session afterward closes clean.

### Task 4 — Docs + stamp

README (the card now lists commands; nothing to configure), the dialect doc's wrapper
consequence section gains the "shipped" note, `mise run ci` + whole-tree lint green.
