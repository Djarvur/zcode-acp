<objective>
Land the Phase-4 plumbing everything else composes on: the D-01 audit-approved SDK
dependency (exact pin + gate discipline), the two missing back-leg method constants
(`session/subscribe`, `session/setModel`), and the ordered notification observer
fan-out in `internal/zcode.Conn` that replaces the single-slot `OnNotification`
(RESEARCH Pattern 4 — the one Phase-3 change this phase needs).

Purpose: without fan-out, a second ACP session silently steals the machine's
notification hook and the first session's turns hang (Pitfall 3). Without the
constants and the dep, no later plan can compile. This plan is pure enablement for
CORE-01..05 — every behavior task in plans 02–05 rides on it.

Output: go.mod with the pinned SDK, a strengthened tidy-diff gate, fan-out with
named contract tests, and zero regressions in the Phase-3 suites.

**User story (phase goal, MVP framing):** As an ACP client (any v1 chat UI), I want
to open a session against ZCode and run a streamed prompt turn end-to-end — live
text and thought chunks with correct cancellation — so that the minimal chat loop is
proven on the real ACP boundary before auth and interaction complexity accrete.
This plan builds the plumbing that loop runs on.
</objective>
