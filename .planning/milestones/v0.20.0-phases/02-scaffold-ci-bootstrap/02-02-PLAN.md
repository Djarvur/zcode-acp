    - idempotency: scrubbing the scrubbed output again changes nothing

    - first line NOT parseable as JSON → exit non-zero, stderr message names the problem (today:
      exit 0, line silently passed through — RED)
    - first line JSON but WITHOUT a `capture` key → exit non-zero with a clear message (today:
      exit 0 — RED)
    - same header-less input WITH `--no-header` → exit 0, line 1 scrubbed like a data line
      (today: the flag is unknown, argv parsing treats it as a third positional and the CLI
      exits 1 with usage — RED on the assertion)

    - empty input → empty output, exit 0 (preserved)
  </behavior>
  <implementation>

    — replace bare `home` occurrences NOT followed by an optional '/' plus a name character,
    using the EXECUTION-VERIFIED form from 02-RESEARCH.md Pattern 7: a global RegExp of the
    escaped home path (add an `escapeRegExp` helper that escapes regex metacharacters) followed

    JSON; require it to be an object containing a `capture` key; on failure write a clear
    one-line stderr message naming the file and the missing contract and exit non-zero. Add a
    `--no-header` flag to the existing argv loop (same style as `--redact-path`: recognized flag,
    no value consumed) that skips the validation and scrubs line 1 as a data line. Preserve the
    empty-input → empty-output early exit (scrub-capture.mjs:154-159) unchanged.
  </implementation>
