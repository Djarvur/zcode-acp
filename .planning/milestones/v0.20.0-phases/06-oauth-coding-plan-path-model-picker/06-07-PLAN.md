<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| backend ask params -> source decision | expectedAccountScope/rejectedProjectTokenFingerprint are backend-controlled inputs driving the re-mint; a forged fingerprint must at worst force one extra mint, never leak or loop |
| PAT cache -> reply envelope | The PAT crosses into the reply; logs/captures must never see it |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-SC | Tampering | npm/pip/cargo installs | high | mitigate | Zero new dependencies (stdlib only) |
| T-06-20 | Denial of Service (turn death) | headersApplied:false or a PAT-less success arm (PITFALL 3) | high | mitigate | The coded-error-envelope-only failure posture (test-locked since Phase 5) carries; the PAT source errors instead of answering the failure-shaped success; the corpus asserts the success arm carries all three fields |
| T-06-21 | Information Disclosure | PAT in responder logs or the corpus golden | high | mitigate | Structural logging (shapes/lengths) only; the corpus carries synthetic placeholder PAT shapes; scan-secrets gates the evidence; the PAT cache struct has no rendering (06-02 lock) |
| T-06-22 | Elevation of Privilege | stale PAT served after a desktop re-login (scope change) | high | mitigate | The expectedAccountScope mismatch arm answers the coded scope-invalidated error before any token is served; the fingerprint-match arm re-mints against the CURRENT scope |
| T-06-23 | Denial of Service | re-mint loop on repeated rejections | medium | mitigate | Exactly-one silent re-mint per ask; a second consecutive rejection surfaces the coded error (vector-locked) |
