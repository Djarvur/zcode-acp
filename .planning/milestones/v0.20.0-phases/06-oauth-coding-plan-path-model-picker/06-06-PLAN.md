**User story (phase goal, MVP framing):** As an ACP client user, I want to
switch the model or thought level from my client's picker and see the wrapper
forward exactly that choice to the backend — carrying my current reasoning
level along so a switch never silently drops it — and get back the refreshed
option list with the now-real selected value.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client set_config_option -> backend mutation | The client's configId/value are untrusted input; validation against the confirmed set gates every backend call |
| backend mutation reply -> client response | The reply snapshot is the only confirmation source; echoing a target as selected before the reply fabricates state |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-SC | Tampering | npm/pip/cargo installs | high | mitigate | Zero new dependencies (the SDK surface already pinned) |
| T-06-17 | Tampering | unvalidated configId/value reaching the backend (arbitrary model injection) | medium | mitigate | Validate-first: the value must be a member of the option's own listed set from the confirmed snapshot; -32602 names the configId and the allowed set; the invalid-vector test proves NO backend frame leaves the wrapper |
| T-06-18 | Denial of Service (turn failure) | a model switch silently dropping options.reasoningLevel (Pitfall 2) | medium | mitigate | The level-carry rule: options rides with the confirmed current level unless the ask changes it; the corpus vector byte-locks the options object on the wire; the level-strict refusal shape is a named negative |
| T-06-19 | Tampering / honesty | currentValue fabricated before the mutation reply confirms | medium | mitigate | The store updates from the REPLY only; the re-emit builds from the reply's settings; the response-before-store-update ordering is impossible by construction (rebuild consumes the reply) |
