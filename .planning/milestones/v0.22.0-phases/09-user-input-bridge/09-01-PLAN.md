# Plan 09-01 — The ask-the-user bridge: `requestUserInput` ↔ form elicitation

## Objective

The AskUserQuestion dialogs reach the Orca UI: `interaction/requestUserInput` bridges
to ONE client-rendered form elicitation; the answer maps back into the dialect's
`{action, content:{answers}}` merge contract (UIB-01..04; UIB-05 is the field pass).

## Wire truth

- Ask params (zcode-src `zcodeUserInputRequestParamsSchema`): questions
  `[{question, header, options: [{value=label, label, description?, preview?}] ≥1,
  multiSelect?}]`; the broker maps options `value = label` (`mapAskUserQuestion`).
- Response: `{action: accept|decline|cancel, content?}`; the tool merge
  (`userInputResponseToBrokerResult` → `normalizeAskUserQuestionResponseContent`)
  expects `content.answers` = record keyed by QUESTION TEXT, values = the selected
  LABELS (`ask-user-question.ts:123-178`); partial answers allowed; decline/cancel
  deny with the reason.
- The client surface: ACP form elicitation (`CreateElicitationRequest{Form:{message,
  mode:"form", requestedSchema, session scope}}` → accept{content}/decline/cancel);
  Orca declares `clientCapabilities.elicitation.form` for the omp card.

## Tasks

### Task 1 — the neutral ask (interact, TDD)

`internal/interact/userinput.go`: `DecodeUserInputAsk(params json.RawMessage)
(UserInputAsk, error)` — questions/prompt/toolCallId; tolerant of the no-questions
shape (empty questions → the free-text arm with the prompt only). The neutral
outcome: `{Action: accept|decline|cancel, Answers map[string]string}`.
RED: `TestDecodeUserInputAsk` (full shape, no-questions, broken JSON).

### Task 2 — the SDK mapping (acpport, TDD)

`internal/acpport/userinput.go`: `BuildElicitationRequest(ask) acp.CreateElicitationRequest`
(per-question index-keyed properties `q1..qn`: single-select → string with OneOf
titled options (label + description) or plain Enum; multiSelect → array of label
enums; title = the question text; message = the ask prompt or the first question;
session scope from the ask) and `MapElicitationOutcome(resp, ask) UserInputOutcome`
(accept.content per-key → answers by question text; array joined ", "; decline/
cancel verbatim).
RED: `TestBuildElicitationRequest` + `TestMapElicitationOutcome` (single, multi,
decline, cancel, empty content).

### Task 3 — the responder row (interact, TDD)

`WithUserInputAsker(ask UserInputAsker)` option; the requestUserInput policy row
becomes `r.handleUserInput`: nil asker → the legacy honest decline (UIB-04, the
existing lock stays green); asker wired → decode → ask → map → the Answer; an asker
error → decline with the reason (never fails the turn).
RED: `TestHandleUserInputBridge` (the asker receives the decoded ask, the answer
carries the mapped content; the error arm declines).

### Task 4 — the production wiring (main.go)

The elicitation ask closure over the client conn (`conn.CreateElicitation`), composed
with acpport's build/map, injected via WithUserInputAsker in wireResponder.

### Task 5 — the composed lock + docs

Tracer/binary lock: a scripted requestUserInput ask surfaces the elicitation request
on the client tee and the scripted answer rides back as the `{answers}` content.
README + the dialect doc's requestUserInput row gain the shipped note. `mise run ci`
+ whole-tree lint green.
