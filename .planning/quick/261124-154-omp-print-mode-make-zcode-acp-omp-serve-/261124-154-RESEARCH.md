## Summary

The failure is fully explained: Orca 1.4.271 invokes
`<override> omp --print --no-session --no-tools --no-extensions --no-skills --no-rules --mode text [--model p/m] [--thinking lvl] @<prompt-file>`
for every text task (chat name, branch name, commit message). The current `omp` arm treats `--print`, `--mode`, `--no-*` and `--thinking` as unknown flags, skips the first positional (which it assumes is the `acp` marker), and falls into the ACP server; Orca sees empty stdout and reports `OMP returned an empty chat name. CLI output: <stderr>`.

The best fix is **not** to reuse the ACP chat turn. The app-server exposes `workspace/generateText`, a one-shot model call: request `{workspace, selection, prompt, querySource}`, response `{text, selection, finishReason, usage?}`. It creates (or reuses) a workspace app, calls the model directly with only the supplied messages/tools, and closes the app. This matches every OMP text-task flag exactly — no session, no tools, no agent loop, no title generation, no turn/reconcile machinery — and avoids the 60 s Orca kill budget's worst overhead. The desktop's own commit-message generator uses this same method with `querySource:"git_commit_message"` (3.17.1 source).

The recommended implementation is therefore: recognize `--print`/`--mode text` in the `omp` arm, read the `@file` prompt (strip the UTF-8 BOM Orca writes, concatenate multi-chunk files), resolve the selection (`--model` or the desktop's `defaultModelSelection`), run one `workspace/generateText` call through the existing `zcode.Conn`, wire the existing interaction responder (PAT/api-key runtime headers, credential-cipher decrypt, official-MCP decline, permission deny), print only `result.text` on stdout, and reuse the existing supervisor staged shutdown. The session path (`acpfront.Front.NewSession` + `Prompt`) is the documented fallback if a live probe shows `workspace/generateText` unusable in host-managed stdio mode.

**Primary recommendation:** implement `internal/texttask` over `workspace/generateText`, gated behind a first live probe against the installed 3.18.2 desktop; keep the session path as the fallback plan, not as the primary.

## OMP CLI Contract (installed Orca 1.4.271)

`[VERIFIED: /tmp/.mount_Orca.AGGkEIK/resources/app.asar.unpacked/out/shared/source-control/ai/generation/commit-message-agent-spec.js:24-36]`
```js
buildArgs: ({ prompt, model, thinkingLevel }) => [
    '--print',
    '--no-session',
    '--no-tools',
    '--no-extensions',
    '--no-skills',
    '--no-rules',
    '--mode',
    'text',
    ...(model && model !== 'default' ? ['--model', model] : []),
    ...(thinkingLevel ? ['--thinking', thinkingLevel] : []),
    prompt
],
```

**Prompt delivery.** `promptDelivery: 'file'` (same file, `:23`). Orca replaces the prompt arg with `@<abs path>` (`Yet`: `i.push(e.attachment?\`@${n}\`:n)`), writes the prompt to `/tmp/orca-generation-<uuid>/prompt-N.txt`, and prefixes each chunk with a UTF-8 BOM (`Zet`: `yield \`\uFEFF${e.slice(t,n)}\``). Prompts larger than 5,242,877 bytes are split into multiple files, spliced as multiple `@file` tokens at the same position. The wrapper must strip one BOM per file and concatenate the chunks with no separator (the files are contiguous slices). The file is mode 0600 and is deleted by Orca after the process closes.

**Success / failure semantics** (`[VERIFIED: installed Orca 1.4.271 out/main/index.js — Iet/Fet/Cb]`):

- Success requires exit code **0** and non-whitespace stdout: `let s=ket(o?.ok?o.text:n,e.operation); if(s)return{success:!0,rawOutput:s,agentLabel:i}`.
- `ket` trims and sanitizes (`cleanGeneratedText`, shape `git`) — fences, leading reasoning blocks and list markers are stripped by Orca, so our job is plain text.
- Empty stdout with exit 0: `Fet` builds `"<label> returned an empty chat name. CLI output: <stderr>"` for `conversation-name` (`Pet={"branch-name":\`branch name\`,"conversation-name":\`chat name\`,...}`; `returned an empty ${r}. CLI output: ${n}`). This is the observed error.
- Non-zero exit: `"<label> CLI command failed with code <n>: <stderr>"` (`jet`).
- Timeout: Orca kills the process at **60,000 ms** (`h=e.timeoutMs??6e4`; `Cb=6e4`; `timedOut seconds:Cb/1000`); the client-side wait is 75,000 ms (`[VERIFIED: out/shared/text-generation/text-generation-client-timeout.js:3-4]` — `exports.TEXT_GENERATION_CLIENT_TIMEOUT_MS = 75_000`).
- stderr is ignored on success; on failure it is the diagnostic detail (stdout detail is deliberately excluded for branch/chat names: `includeStdoutDetail` false for `branch-name`/`conversation-name`/`dictation-cleanup`).

### Flag disposition

| Flag | Disposition | Rationale |
|------|-------------|-----------|
| `--print` | **Essential** — selects non-interactive text mode | Without it the current ACP path runs. |
| `--mode text` | **Essential** — assert text-only; unknown values are a usage error (exit 2) | The app-server session `mode` enum has no `text` (`plan|build|edit|yolo|guarded|auto`); text-only is expressed by the direct model call. |
| `--no-session` | **Satisfied by `workspace/generateText`** (no session at all). On the fallback session path: accept, never resume, close at the end; the app-server has no non-persistent create | `persistence` is only `immediate|deferred`, not "none". |
| `--no-tools` | **Satisfied** — omit `tools` from the generateText params. Fallback path: `toolAllowlist: []` in `session/create` (V-SRC; `[]` is truthy in `tOn`, so the allowlist path passes an empty set — probe live before relying on it) | `[VERIFIED: 3.18.2 bundle — Zat]` — `toolAllowlist:m.array(hn).optional()`; `[VERIFIED: 3.18.2 bundle — oUe/tOn]` |
| `--no-extensions`, `--no-skills`, `--no-rules` | **Accept and ignore** — no per-request app-server switch; the direct model call has no agent loop, so the effect is inherent | The create schema has no such keys (`Zat`). |
| `--model provider/model` | **Essential when present** — selection; `default` is never passed by Orca | `[VERIFIED: cmd/zcode-acp/main.go:405-434]` — split on the first `/`. |
| `--thinking level` | Map to `selection.options.reasoningLevel`; optional | Pass through verbatim; backend validates. |
| prompt `@file` | **Essential** — read, strip BOM, concatenate chunks | See above. |
| unknown flags | Tolerate (future Orca versions), one debug line | Existing `ompParse` posture. |

### Exit codes and stdio (recommended)

- `0` — generated non-whitespace text was printed to stdout.
- `1` — runtime/generation failure: discovery, spawn, auth-required failure, wire error, empty text, timeout, child lost.
- `2` — invalid argv/config: missing prompt, bad `--model` shape, `--thinking` without `--model`, unsupported `--mode`, unreadable prompt file.
- stdout: the final text only; add exactly one trailing newline if absent. No JSON, no usage dump, no logs. Orca trims, so a trailing newline is optional but conventional.
- stderr: all logs; may be non-empty on success (Orca ignores it). Keep prompt content and credentials out of every log line.
- Empty generated text: prefer exit 1 with a concise stderr line (gives Orca `CLI command failed with code 1: ...`) over exit 0 + empty stdout (`returned an empty chat name`). This is a judgment call; both are failures to Orca.

### Adjacent gap discovered (out of scope, high value)

Orca probes the omp model catalog with `models --json` (`[VERIFIED: out/shared/agent-session/options/model-catalog/omp-model-list-probe.js:8]` — `exports.OMP_MODEL_LIST_ARGS = ['models', '--json'];`) and parses `{models:[...]}` with `provider`/`id`/`selector`/`name`/`contextWindow` keys. ### Flow in `runOmpText`

```
ompParse → version? → unsupported mode? → read @file prompt
  → discoverInstall → startSupervised → NewConn
  → keys + buildCodingPlanMachinery + buildFront
  → wireResponder(deny permission, nil user-input asker, PAT/static headers, cipher decrypt)
  → resolve selection (flag → provider_config default)
  → [auth if selection/provider requires it]  // Front.Authenticate, bounded
  → conn.Call(workspace/generateText, {workspace, selection, prompt, querySource})
  → decode text; empty/whitespace → error
  → print text + "\n" to stdout
  → staged shutdown (supCancel → wait startDone → spawnCancel)
  → exit 0
```

Text mode must **not** construct `acpport.NewAgentSideConnection` (the ACP server). Orca's preparation wrapper writes the prompt files, emits `ORCA_GENERATION_READY` on stderr, then `exec`s the binary; once the record stream is delivered it ends the child's stdin (`p.stdin?.end(...)`). Text mode therefore starts with the prompt file already present and must ignore stdin entirely — an ACP server would read the immediate EOF as a client disconnect.

### Auth policy (avoid side effects on the happy path)

Do **not** call `NewSession`/`ensureSilentAuth` for text tasks — `ensureSilentAuth` can mint a PAT and push the account overlay on every invocation (`[VERIFIED: internal/acpfront/auth.go:721]` — `const autoAuthBudget = 7 * time.Second`; `:733-757`). Choose by the resolved selection:

| Selection provider | Wrapper api key | Action before generateText |
|--------------------|-----------------|----------------------------|
| `account:*` | any | `Front.Authenticate(ctx, AuthMethodZaiCodingPlan)` (keyring → entitlement → PAT → push/refresh → probe/read-back), bounded |
| `zai-api` | set | `Front.Authenticate(ctx, AuthMethodZaiAPIKey)` (push/refresh/read-back), bounded; on read-back failure log and proceed |
| `zai-api` | absent | No auth; the app-server's own `provider_config.json` may carry the key. On a `-32031`/headers failure, fail with the coded error |
| any other (e.g. `OpenCodeGo`) | any | No auth; personal providers carry their key in `provider_config.json`, read by the child |

If the desktop is on the coding plan but Orca passes the builtin `zai-api/...` selection, mirror `applyConfiguredModel`'s rebind (`[VERIFIED: internal/acpfront/front.go:1036-1039]`) and run the coding-plan chain. Resolve the account provider from the built entitlement overlay rather than hardcoding it if time allows; otherwise document the limitation.

### Selection default

When `--model` is absent (Orca's `default` model id is filtered out; `--model` is omitted), read `~/.zcode/v2/provider_config.json` → `config.defaultModelSelection` (same file `ChildEnv` points the child at; the desktop's `preferredSelection` resolves from the configured default: `[VERIFIED: zcode-src packages/provider/src/model-selection-config.ts:28-59]`). ## Risks and Gotchas

1. **60 s kill budget.** Orca kills at 60 s; the app-server itself aborts `generateText` at 60 s. Bound the whole run to ~50 s (e.g., 40 s generation + 10 s shutdown) and exit 1 with a clear stderr message rather than being SIGKILLed. This is the strongest argument for the one-shot method over a session turn.
2. **`ensureSilentAuth` side effects (fallback path).** `NewSession` can run the full coding-plan chain — keyring probe, eager PAT mint, account push, probe create/setModel/close — on every text task. Avoid it; if the fallback path is used, add a `WithSilentAuth(false)` option or accept the cost knowingly.
3. **Title generation (fallback path).** A created session with a first prompt can trigger the app-server's own title generation (extra model call/spend). Send `titleGenerationEnabled:false` (V-SRC create key) if the session path is used.
4. **Session persistence.** `--no-session` cannot be fully honored on the session path (`persistence` is only `immediate|deferred`; no delete method). The one-shot method satisfies it exactly.
5. **`workspace/generateText` is V-SRC, not V-EXP.** Gate the implementation behind a live probe; keep the session fallback. The method's handler, params/result schemas, 60 s timeout and desktop caller are all source-verified, but this project has not exercised it on the wire.
6. **Custom provider credentials.** The user's `OpenCodeGo` provider is an `api-key` rule in `~/.zcode/v2/provider_config.json`; the child reads that file itself. The wrapper must not read or log the key. For account/coding-plan providers, the PAT/overlay chain is still required.
7. **Prompt BOM and chunking.** Strip one UTF-8 BOM per `@file`; concatenate multiple chunks with no separator. A naive `strings.TrimSpace` on the whole file is fine for the BOM? No — trim space does not remove U+FEFF; strip the BOM explicitly.
8. **Prompt size / path safety.** Cap the prompt (e.g., 16 MiB) to avoid OOM; read only regular files. The path comes from Orca; do not follow a symlink into a secret without at least a debug log.
9. **Slash intercept (fallback path).** `Front.Prompt` consumes `/model ...` prompts as a model-switch command (`promptModelSlash`). A literal text task whose prompt starts with `/model` would be hijacked. Add a literal prompt entry point if the session path is chosen.
10. **stdout purity.** Every log must go through the stderr slog (already set in `runOmp`); the app-server's stdout is consumed by the Conn; the child's stderr is forwarded to `os.Stderr` (`[VERIFIED: internal/supervisor/spawn.go:290-315]`). Never print a usage dump on stdout (`ompFlagSet` already uses `io.Discard`).
11. **`--mode` values.** The app-server session mode enum has no `text` (`[VERIFIED: 3.18.2 bundle — m8]` — `m8=m.enum(["plan","build","edit","yolo","guarded","auto"])`); never forward `--mode text` to `session/create`. Unknown `--mode` values should exit 2, not silently start ACP.
12. **Model `default`.** Orca omits `--model` when the model is `default`; the wrapper must resolve a selection from provider_config or fail actionably. Do not pass `default` as a provider/model.
13. **Cancellation.** `workspace/cancelGenerateText` is in the app-server's bypass lane but the Conn exposes only `Stop` (session/stop) on that lane (`[VERIFIED: internal/zcode/call.go:196-217]`). For v1, let process shutdown abort the call; add a `CancelGenerateText` bypass helper only if needed.
14. **Signal handling.** Orca may SIGKILL at 60 s; the child app-server sees stdin EOF when the wrapper dies and exits on its own. An explicit SIGTERM handler is optional, not required for correctness.
15. **Lint.** The strict config (funlen, cyclop 15, gocognit 30, lll 120, err113, wrapcheck, tagliatelle) applies; new code must be decomposed and errors wrapped with sentinels. No new `go.mod` requires (tidy gate expects exactly one require line).
16. **Real-tier spend.** The live probe is one tiny model call; record it in the quota ledger, use the `realdesktop` tag + `ZCODE_ACP_REAL_E2E=1`, and never run it in CI.
17. **Non-git / temp cwd.** `workspace/generateText` does not need git; it needs an existing absolute `workspacePath`. Orca passes its target workspace path. A non-git directory is fine (the workspace ref is host-opaque), but do not substitute a temp dir for the given cwd — the app may resolve workspace identity/trust from it, and the prompt already carries all task context. Validate `filepath.IsAbs` + `os.Stat`, and fail with exit 1/2 if invalid.
18. **Unentitled or unknown model.** A provider/model the registry cannot resolve surfaces as a wire error; surface it coded (numeric code + a short message) and exit 1. Do not silently fall back to another model for text tasks — a wrong commit message/title is worse than an honest failure.

## Security Domain

ASVS level 1, applicable categories:

| ASVS | Applies | Control |
|------|---------|---------|
| V2 Authentication | No (new surface) | The wrapper's auth is out of band; `Front.Authenticate` is existing. |
| V3 Session Management | No | Text mode creates no session on the recommended path. |
| V4 Access Control | No | No new authorization surface. |
| V5 Input Validation | Yes | `cwd` absolute; model shape `provider/model`; `--mode` enum; prompt file regular/size-capped; strict JSON params; no shell. |
| V6 Cryptography | No new crypto | PAT mint/keyring decrypt reuse existing code; never log tokens, prompts, or prompt files. |

Threat notes: a hostile caller could pass `@/etc/shadow` and have it sent to the model (the real omp CLI has the same attachment semantics). The caller already runs as the user; still, cap size, read regular files only, and avoid echo of the prompt in logs. The app-server child env is the existing allowlist (`PATH`, `HOME`, Electron, builtin/personal config paths) — keep it.
