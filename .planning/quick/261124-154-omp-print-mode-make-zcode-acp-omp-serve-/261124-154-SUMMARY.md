**2. [Rule 1 - Bug] `backend.stop` had to be idempotent**

- **Found during:** Task 2 backend extraction.
- **Issue:** The plan’s `run` returns the stop error and also defers `Close`, which calls `stop`; a second receive on the single-delivery `startDone` channel would block the full 15 s watchdog and fabricate `errShutdownWatchdog` on every run.
- **Fix:** `stop` runs its body under `sync.Once` and returns the recorded outcome; `Close` logs a stop error (only on the failure path) before joining the conn and firing `spawnCancel`.
- **Files modified:** `cmd/zcode-acp/main.go`.
- **Verification:** `TestAgentBinaryEndToEnd`, `TestOmpText*`, and the whole-tree race suite stay green; no test observes a duplicate teardown.
- **Committed in:** `cd21352`.

**3. [Rule 3 - Blocking] `main_test.go` constant/arity updates**

- **Found during:** Task 2 gate.
- **Issue:** Updating `wireResponder`’s arity is mandatory for compilation; adding the text tests also pushed three pre-existing `main_test.go` literals over `goconst`’s threshold (`providerZaiAPI`, `e2eModel`, `zai-api` counts).
- **Fix:** Passed the ACP bridge forwarder at the existing call site and used the existing/production constants at the affected literals.
- **Verification:** `TestWiringCodingPlanSeams` and the full cmd suite green; lint count restored to exactly 10.
- **Committed in:** `cd21352`.

**4. [Rule 1 - Bug] A custom querySource must carry an explicit `maxOutputTokens`**

- **Found during:** the orchestrator’s guarded live probe (post-plan Task 3 human-check).
- **Issue:** the probe reached the wire and failed `-32603: maxOutputTokens is outside the model option range`. Source-verified in the installed 3.18.2 bundle: `workspace/generateText`’s handler builds `options` with `maxOutputTokens` only for querySources other than its special `git_commit_message` path, and that path binds the desktop’s own model profile (which supplies the option); a wrapper querySource gets no profile, and the model’s strict `prepareRequest` validator (`pha(optionSpecs, {...this.options, ...request.options})`) throws when the value is undefined. The plan’s “omit `maxOutputTokens`” assumption was therefore disproven by the live wire, not a design choice.
- **Fix:** the request now carries top-level `maxOutputTokens: 1024`. 1024 is the smallest cap any builtin registry rule allows (the `glm-4v-flash` rule; every other builtin rule is >= 4096) and is ample for Orca’s text tasks (chat/branch names; commit messages are capped at 1000 characters). The two absence assertions became presence assertions (`params.maxOutputTokens == 1024`), with only `tools`/`messages` still forbidden.
- **Files modified:** `internal/texttask/generate.go`, `internal/texttask/generate_test.go`, `cmd/zcode-acp/text_test.go`.
- **Verification:** `go build ./...` plus the Task 1/Task 2 focused gates green (texttask 1.27 s, interact 2.39 s, cmd 13.98 s, fake 23.80 s, all ok); pinned golangci-lint 2.15.0 still exactly the 10 pre-existing `internal/acpfront/*_test.go` findings, zero in the touched files.
- **Committed in:** the deviation-fix commit `fix(261124-154): carry maxOutputTokens in the text-task request`, applied on top of `bc5210f` (hash reported to the orchestrator with this fix).
