# Quick Task 261124-w84 Summary

**Recoverable model-selection validation now preserves the live ACP session and its byte-identical confirmed settings across both the config-option picker and `/model`, while fatal or ambiguous failures retain full teardown.**

## Root Cause

Both setModel error branches called `teardownAfterPickerRefusal` unconditionally. A correctable unsupported-reasoning-effort refusal therefore removed the registry entry, cwd, and confirmed settings; the client's next operation saw an unknown session instead of being able to retry with a valid selection.

## Accomplishments

- Added `isRecoverableSetModelError` with fail-closed `errors.As` handling and exact structured-data precedence.
- Preserved picker and `/model` sessions for numeric invalid-params, the exact `ModelProtocolError`/`invalid_model_request` pair, and the two narrow data-less unsupported-reasoning message shapes.
- Proved registry membership, cwd, and byte-identical settings survive recoverable refusals, and that later valid operations succeed using reply-confirmed settings without a session/close frame.
- Locked malformed, null, wrong-typed, empty, and unrecognized present `-32603` data as fatal even when the message resembles recoverable validation.
- Retained full teardown for resource-not-found/dead targets, method-not-found, unknown internal errors, transport failures, and cancellation.
- Preserved the existing ACP-facing `-32603` error mapping and all validation-before-wire, settings-merge, and `CloseSession` behavior.

## Decisions Made

- Present structured data always wins over message compatibility: malformed or unrecognized data cannot be rescued by validation-shaped text.
- Numeric invalid-params is recoverable without inspecting message or data, as required by the plan.
- Unknown failure modes remain fatal so the wrapper never preserves a session whose backend target may be dead.
