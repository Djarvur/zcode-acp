Locked job shape (insert between `sanity` and `govulncheck`; comments are part of the shape):

```yaml
  windows:
    # Native Windows gate. The job name is NOT a branch-protection required
    # context: the Linux sanity job above keeps its name and required set.
    name: build / vet / test (windows)
    runs-on: windows-latest
    # Watchdog only: the same race suite runs ~2 min on this machine; Windows
    # runners compile cgo/race code more slowly.
    timeout-minutes: 25
    # The Linux job's POSIX installer/PATH steps cannot run on Windows.
    defaults:
      run:
        shell: pwsh
    steps:
      # Windows checkouts default to Git for Windows' core.autocrlf=true; the
      # checked-in .gitattributes forces LF for testdata, so the byte-exact
      # golden fixtures match what the Go tests construct. Do not remove it.
      - uses: actions/checkout@v4

      # Native Windows installer (mise.run is the canonical distribution
      # point; `curl https://mise.run | sh` does not run on Windows).
      - name: Install mise
        run: |
          irm https://mise.run/powershell | iex

      # The installer writes %USERPROFILE%\.local\bin and updates the user
      # Path; GitHub steps only see paths exported through GITHUB_PATH.
      - name: Add mise to PATH
        run: |
          "$env:USERPROFILE\.local\bin" | Out-File -FilePath $env:GITHUB_PATH -Encoding utf8 -Append

      # Only the Go pin is needed: build, vet and test. The version still
      # comes from mise.toml [tools] go — never a second pin (D-02).
      - name: Install Go from mise.toml
        run: mise install go

      - name: build
        run: mise run build

      - name: vet
        run: mise run vet

      # Same task the Linux job runs: go test -race -count=1 ./... . The
      # Windows race runtime needs cgo; windows-latest ships mingw-w64 gcc
      # at C:\mingw64\bin on PATH (Install-Mingw64.ps1).
      - name: test (go)
        run: mise run test
```

```gitattributes
# Windows CI runners check out with Git for Windows' core.autocrlf=true, which
# rewrites LF to CRLF in the working tree. The Go suite byte-compares golden
# transcripts and fixtures (fake.CompareGolden), so testdata must be checked
# out exactly as stored on every platform. All current testdata files are

```

Verified planning facts:

- mise ships a native Windows installer: `irm https://mise.run/powershell | iex`. The installer defaults `MISE_INSTALL_PATH` to `$HOME\.local\bin\mise.exe` and prepends the install directory to the user Path (installer script header and Add-ToUserPath). It does not persist into a later GitHub step, so the job must export the directory through GITHUB_PATH.
- mise's Go core backend supports Windows (jdx/mise PR #2990 "feat: support go core plugin on windows", merged 2024-11-11; `src/plugins/core/go.rs` selects `windows` in its platform mapping). mise tasks run on Windows (task-shell fixes #12066, #12274, #13866), and the task executor documents `cmd /c` as the default Windows task shell (`src/task/task_executor.rs`), so the plain `go build|vet|test` task bodies need no POSIX shell. `mise install <bare tool>` installs the version the config requests — confirmed with local `mise install --help`.
- Go supports the race detector on windows/amd64, and it requires cgo plus a C compiler with mingw-w64 runtime v8 or newer (go.dev race-detector documentation). actions/runner-images installs mingw64 into `C:\mingw64` and adds `C:\mingw64\bin` to the machine PATH via `images/windows/scripts/build/Install-Mingw64.ps1`; both the windows-2022 (gcc 14.2.0) and windows-2025 (gcc 15.2.0) images list it.
- Windows checkouts default to Git for Windows' core.autocrlf=true, and actions/checkout exposes no autocrlf input (actions/checkout issues #135 and #226, both open; the recommended durable fix is a checked-in .gitattributes). The repo has no .gitattributes today and no testdata file contains a CR byte; `fake.CompareGolden` compares os.ReadFile bytes to constructed LF bytes (`internal/zcode/fake/golden.go`), so a CRLF checkout would fail the golden suite.
- Locally simulated with `git -c core.autocrlf=true clone`: without a rule a testdata fixture checks out CRLF, while `**/testdata/** text eol=lf` checks out LF and keeps textual diffs; `git check-attr text eol` then reports `text: set` and `eol: lf`.
- Branch protection requires exactly `build / vet / lint / test / tidy`, `govulncheck`, and `secret-scan` (`.planning/milestones/v0.20.0-phases/02-scaffold-ci-bootstrap/protection-body.json`). The new Windows check is deliberately not added: this task changes workflow YAML only, never repository settings.
- Baseline at HEAD is green: `go build ./...`, `go vet ./...`, `go test -race -count=1 ./...` (about 2 minutes), `GOOS=windows GOARCH=amd64 go build ./...`, `GOOS=windows GOARCH=amd64 go vet ./...`, `bash experiments/check-docs.sh`, and `bash experiments/scan-secrets.sh` all pass.

Do not add setup-go, golangci-lint-action, secrets, `continue-on-error`, or a second tool pin. Preserve the pre-existing untracked `.planning/quick-batches/` directory.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub-hosted Windows runner to repository code | Every push and pull request executes the repository's Go tests on a fresh windows-latest VM; the workflow token rights and secret exposure bound the blast radius. |
| mise.run to Windows runner | A remote PowerShell installer is fetched and executed before any repository tooling runs. |
| mise.toml to Go toolchain | The new job's only tool-version source; a literal Go version in YAML would break the single-source rule and drift from the Linux job. |
| Workflow YAML to branch protection | Job names are required-check contexts; altering `sanity` would change what can merge. |
| Git checkout to byte-exact fixtures | Windows core.autocrlf could rewrite testdata, silently changing what the golden tests assert. |
